Daily Routines

Recurring

A realistic breakdown of how your day flows in production AI work — from overnight eval review to EOD commit discipline.

09:00 — Morning Standup
Sync on blockers, model regressions, deployment status
Check overnight CI/CD runs, eval dashboards, and on-call alerts. Flag latency spikes or prompt injection incidents from production logs.
09:30 — Eval & Monitoring Review
Review automated eval results, model output drift, error rates
Pull the daily eval report. Compare against baseline. Triage anomalies in cost-per-call or token usage. Log decisions in the ops runbook.
10:00 — Core Dev Block
Feature development: prompt engineering, RAG pipeline, API integration
Focus on one deliverable — building a retrieval chain, refining a system prompt, or writing Python wrappers around LLM APIs. Commit atomic, tested changes.
12:30 — Docs + Async Comms
Update prompt logs, internal docs, respond to cross-team queries
Document every prompt version with rationale and eval results. Update the shared model decision log and respond to data team questions.
14:00 — Second Dev Block
Testing, iteration, PR review
Write unit tests for LLM output parsing and fallback logic. Review PRs for prompt safety and correct async handling. Run integration tests against staging.
16:00 — Cross-Functional Sync
Product, design, or data science collaboration
Translate product requirements into LLM feature specs. Work with data teams on embedding pipelines. Collaborate with design on AI UX edge cases.
17:00 — EOD Wrap & Handoff
Push commits, update tickets, queue overnight jobs
Ensure all WIP is committed and documented. Queue long-running eval jobs or fine-tune runs overnight. Update sprint tracker and set production alerts.

⛓ Prompt ChainingPattern
Chain multiple LLM calls where each output feeds the next step.
async def chain_prompts(document: str) -> dict: # Step 1: Extract key entities entities = await call_llm_async( system="Extract named entities as JSON", user=document ) # Step 2: Summarize using extracted entities as context summary = await call_llm_async( system="Summarize the document, referencing key entities", user=f"Entities: {entities}\n\nDocument: {document}" ) # Step 3: Generate action items from summary actions = await call_llm_async( system="Generate 3 actionable next steps as a JSON list", user=summary ) return {"entities":entities, "summary":summary, "actions":actions}
🔁 Retry Logic with Exponential BackoffReliability
Production-grade retry wrapper with jitter and circuit breaker awareness.
import asyncio, random from typing import TypeVar, Callable, Awaitable T = TypeVar('T') async def with_retry( fn: Callable[..., Awaitable[T]], max_attempts: int = 3, base_delay: float = 1.0, retryable: tuple = (RateLimitError, APITimeoutError), ) -> T: for attempt in range(max_attempts): try: return await fn() except retryable as e: if attempt == max_attempts - 1: raise # Exponential backoff with full jitter cap = base_delay * (2 ** attempt) delay = random.uniform(0, min(cap, 30)) await asyncio.sleep(delay)
💰 Cost Tracking DecoratorCost
Automatically track token usage and cost per LLM call to a Prometheus/StatsD sink.
from functools import wraps from dataclasses import dataclass # Model pricing per 1M tokens (input, output) PRICING = { "claude-sonnet-4-5-20250929": (3.00, 15.00), "claude-haiku-4-5-20251001": (0.80, 4.00), "gpt-4o": (2.50, 10.00), } def track_cost(fn): @wraps(fn) async def wrapper(*args, **kwargs): resp = await fn(*args, **kwargs) model = kwargs.get("model", "unknown") inp, out = PRICING.get(model, (0,0)) cost = (resp.usage.input_tokens * inp + resp.usage.output_tokens * out) / 1_000_000 metrics_emit("llm.cost_usd", cost, tags={"model":model}) return resp return wrapper
📦 Batch Processing with Rate ControlScale
Process large document batches without hitting rate limits.
import asyncio from asyncio import Semaphore async def batch_process( items: list, process_fn, concurrency: int = 5, batch_size: int = 20, ) -> list: sem = Semaphore(concurrency) results = [] async def bounded(item): async with sem: return await process_fn(item) # Process in batches to avoid overwhelming the event loop for i in range(0, len(items), batch_size): batch = items[i:i+batch_size] batch_results = await asyncio.gather( *[bounded(x) for x in batch], return_exceptions=True ) results.extend(batch_results) return results
🛡 Fallback Strategy ChainReliability
Try primary model, fall back to cheaper model, then serve cached response.
async def with_fallbacks(prompt: str, cache: Cache) -> str: # Level 1: Try primary (best quality) try: return await call_llm(prompt, model="claude-sonnet-4-5-20250929") except APIError: log_fallback("primary_failed") # Level 2: Try cheaper/faster model try: return await call_llm(prompt, model="claude-haiku-4-5-20251001") except APIError: log_fallback("secondary_failed") # Level 3: Serve stale cached result or static fallback if cached := await cache.get_stale(prompt): return cached raise AllProvidersFailedError("All fallbacks exhausted")

Common Hallucination Triggers & Mitigations

Safety

Understanding why LLMs hallucinate is the first step to preventing it in production.

TriggerWhy It HappensMitigationPriority
Training data gapsModel interpolates between known facts when knowledge is sparseUse RAG; acknowledge unknown in system prompt; test on OOD queriesCritical
Leading questionsModel complies with implied premise rather than correcting itUse neutral phrasing; include "say I don't know if uncertain" in system promptCritical
Context too longAttention dilutes; model reverts to prior rather than reading contextTrim context to most relevant chunks; use "lost in the middle" mitigationCritical
High temperatureSampling randomness produces plausible-sounding but incorrect outputsUse temperature 0–0.3 for factual tasks; reserve high temp for creative onlyHigh
Numeric/date precisionModels are poor at exact arithmetic and date calculationsAlways use tools/code for math; never trust LLM arithmetic in productionHigh
Proper nouns / rare entitiesSparse training data on obscure names causes confabulationInject entity definitions in context; entity-linking pre-processingHigh
Multi-step reasoningErrors compound across reasoning stepsForce chain-of-thought; verify intermediate steps; use structured outputsMedium
Instruction conflictsContradictory instructions cause unpredictable behaviorAudit system prompts for contradictions; test with adversarial inputsMedium

Python — Full Jitter Backoff
import random, asyncio def full_jitter(attempt: int, base: float=1.0, cap: float=60.0) -> float: """AWS-style full jitter: sleep = random(0, min(cap, base * 2^attempt))""" return random.uniform(0, min(cap, base * (2 ** attempt))) # Usage in retry loop for i in range(5): try: return await api_call() except RateLimitError: await asyncio.sleep(full_jitter(i))

Anti-Patterns

Warnings
⊘Prompt Anti-Patterns+
  • DO: Version + eval every prompt change — DON'T push edits without eval results
  • DO: Use XML delimiters for user input — DON'T concatenate raw user strings
  • DO: Keep system prompts focused — DON'T stuff 2000 words of instructions
  • DO: Test edge cases exhaustively — DON'T only test the happy path
⊘Architecture Anti-Patterns+
  • DO: Abstract the LLM provider — DON'T couple business logic to SDK calls
  • DO: Cache aggressively — DON'T make duplicate LLM calls for the same input
  • DO: Async everything — DON'T block event loops with synchronous calls
  • DO: Route simple tasks to cheap models — DON'T use Opus for intent classification
⊘Data Anti-Patterns+
  • DO: Scrub PII before API calls — DON'T send raw user data to LLM endpoints
  • DO: Chunk by semantic unit — DON'T use arbitrary character splits
  • DO: Validate retrieved context — DON'T blindly inject all retrieved docs
